1. 旁聽生註記

- 旁聽是「某門課的修課方式」，綁在該門課的選課紀錄上，不是帳號身分
  - 同一人可以 A 課正修、B 課旁聽
  - 沒有新增「旁聽生」角色
- 旁聽一樣佔名額、一樣算學費，差在這門課不用交作業、沒成績、沒學分

2. 新增 api [Patch] /enrollment/audit? (role: creator, admin, manager)

- query: course_id, student_id
- request.is_audit 欄位 (bool)
  - true = 標記為旁聽，false = 取消旁聽
- 老師打會回 403，學生打也會回 403
- 若該學生沒有修這門課，會回傳錯誤訊息：「該學生並未修習此課程」(400)
- 後端會一併記錄是誰改的、什麼時候改的

3. 新增 api [Patch] /enrollment/audit/batch? (role: creator, admin, manager)

- 一次處理同一門課的多位學生，教務勾選一批人後送出用
- query: course_id
- request.student_ids 欄位 (array)
- request.is_audit 欄位 (bool)
  - 整批一起標記或一起取消，要一次做兩個方向請分兩次呼叫
  - 重複的 student_id 會自動去重
- 新增 response.data.updated_count 欄位 (int)
- 新增 response.data.not_enrolled_student_ids 欄位 (array)
  - 名單中沒有修這門課的人「不會」中斷整批作業
  - 其餘的照樣更新成功，沒修課的列在這裡讓前端提示
- 若 student_ids 為空，會回傳錯誤訊息：「student_ids 不能為空」(400)

4. 調整 [Get] /student-list?course_id=

- 新增 response.data.students[].student_id 欄位 (string)
- 新增 response.data.students[].departments 欄位 (array)
  - master_of_divinity : 道學碩士
    master_of_christian_studies: 基督教研究碩士
    bachelor_of_theology: 神學學士
    lay_leadership_program: 信徒領袖科
    pastoral_program: 拿會按牧必修
- 新增 response.data.students[].is_audit 欄位 (bool, nullable)
  - 旁聽標記屬教職員資訊，學生身分呼叫這支時 is_audit 一律回 null
  - 老師、管理員、院長才拿得到 true / false
  - 科別 (departments) 學生看得到，不受影響

5. 調整 [Get] /score/list-sheet?course_id=

- 新增 response.data.data_rows[].departments 欄位 (array)
- 新增 response.data.data_rows[].is_audit 欄位 (bool)
- 旁聽生「仍然會出現在成績簿」，老師才看得到人
  - 但該列 scores[].score 一律為 null
  - 前端請依 is_audit 把該列鎖成不可輸入
- 注意: scores[].score 的型別由 number 改為 nullable
  - 非旁聽生的行為完全不變（沒有成績時仍然是 0）
  - 只有旁聽生才會是 null

6. 調整 [Post] /score/submit-score

- 若該學生於此課程為旁聽，會回傳錯誤訊息：「該學生於此課程為旁聽，無法評分」(422)
- 已經有分數的人被改成旁聽後，成績簿就讀不到分數、也不能再改
  - 舊分數不會被刪除，之後取消旁聽就會恢復顯示與可評分

7. 調整 [Post] /score/my-score?course_id= (role: student)

- 新增 response.data.is_audit 欄位 (bool)
- 旁聽此課程時 is_audit = true，且 scores 必為空陣列
  - 不回傳任何分數

8. 調整 [Put] /assignment/submit?assignment_id=

- 若此課程為旁聽，會回傳錯誤訊息：「此課程為旁聽，無需繳交作業」(422)

9. 調整 [Get] /assignment/student/list-by-course?course_id= (role: student)

- 新增 response.data.is_audit 欄位 (bool)

10. 調整 [Get] /assignment/teacher/list-submissions?assignment_id= (role: teacher)

- 新增 response.data.list[].is_audit 欄位 (bool)

11. 調整 [Get] /course-management/student/get-current-term (role: student)

- 新增 response.data.courses[].is_audit 欄位 (bool)
- 新增 response.data.courses[].earned_credit 欄位 (int)
  - 旁聽為 0，其餘等同 credit
  - 原本的 credit 欄位不變，仍是該課程的學分數
- 旁聽課「仍然會列出」，只是實得學分 0

12. 調整 [Post] /course-management/get-list

- 新增 response.data.courses[].is_audit 欄位 (bool, nullable)
- 新增 response.data.courses[].earned_credit 欄位 (int, nullable)
  - 旁聽為 0，其餘等同 credit
  - 只有學生身分呼叫時才有值，其他身分一律為 null
    （旁聽是「某位學生在某門課」的狀態，對老師/管理員沒有意義）
- 這支是「修課記錄（含歷年）」的資料來源
  - 這支「不會」依 end_date 過濾，已結束的課也照樣回傳
  - 學生看到 view_permission = true 就代表「這門課我修過」
  - 所以前端可以用這支列出歷年所有修過的課，含已結束的學期
  - 搭配 [Post] /score/my-score 就能取得各課成績（my-score 對已結束的課也可用）
- 因此成績單不需要另開新 api，用這兩支組即可

13. 名額與學費

- 旁聽跟正科生走同一張選課紀錄，enrollment_count 本來就把旁聽算進去
  - 滿額一樣不能再加

- 不需要做資料轉檔，行為與目前完全一致

15. 上傳檔案 v3（新增，v2 維持原樣不受影響）

- 起因: v2 的 [Post] /upload/v2/sign 在「檔案還沒真的傳上去」時就回傳了可存檔的網址
  - 如果那次上傳失敗（斷線、簽名過期、使用者換檔案），前端還是會把網址存進資料庫
  - 結果就是資料庫記著一個指向不存在檔案的網址，點下載才會爆
  - 正式站盤點過: 1609 筆檔案引用中有 14 筆是斷的，全部在課程大綱

- v3 的差別: 簽名時「不」給可存檔的網址，一定要上傳完再跟後端確認過才給
- v2 沒有移除，不影響現有功能，也不訂停用時間
  - 但請前端有空的時候把上傳改接到 v3
  - 在改接完成之前，斷鏈的檔案還是會繼續產生（只是被 /download 的補救擋著不讓使用者看到）
  - 改接完成後通知我，我再把 v2 移除

- 詳細步驟
  - 步驟1: 取得上傳網址

    ```
    curl --location 'https://campus-system-dev-749888051547.asia-east1.run.app/upload/v3/sign' \--header 'Content-Type: application/json' \--data '{"file_name": "四福音-導論.pdf","content_type": "application/pdf"}'
    ```

    會得到這樣的response

    ```
    {
        "data": {
            "object_name": "uploads/2026-09/b95b387d-bf5d-4625-90b5-7dc1392b1f48_四福音-導論.pdf",
            "upload_url": "https://storage.googleapis.com/campus-system-dev/uploads/2026-09/b95b387d-bf5d-4625-90b5-7dc1392b1f48_四福音-導論.pdf?X-Goog-Algorithm=GOOG4-RSA-SHA256&X-Goog-Credential=...&X-Goog-Expires=3600&X-Goog-Signature=...",
            "expire_minutes": 60
        }
    }
    ```

    upload_url 在第二步使用，object_name 在第三步使用。
    這裡「不會」回傳可以存進資料庫的網址，這是刻意的。

  - 步驟2: 上傳檔案

    ```
    curl --location --request PUT '<步驟1的 upload_url>' \
    --header 'Content-Type: application/pdf' \
    --data-binary '@/path/to/四福音-導論.pdf'
    ```

    ps:請注意content-type要和步驟1一致

  - 步驟3: 確認上傳結果

    ```
    curl --location 'https://campus-system-dev-749888051547.asia-east1.run.app/upload/v3/confirm' \--header 'Content-Type: application/json' \--data '{"object_name": "uploads/2026-09/b95b387d-bf5d-4625-90b5-7dc1392b1f48_四福音-導論.pdf"}'
    ```

    會得到這樣的response

    ```
    {
        "data": {
            "url": "gs://campus-system-dev/uploads/2026-09/b95b387d-bf5d-4625-90b5-7dc1392b1f48_四福音-導論.pdf",
            "size": 426514,
            "content_type": "application/pdf"
        }
    }
    ```

    這裡的 url 才是可以存進資料庫的網址。

  - 錯誤情況
    - 步驟2沒做或失敗就直接呼叫步驟3，會回傳錯誤訊息：「檔案尚未上傳成功，請重新上傳後再確認一次。」(422)
    - 上傳到一半斷掉導致檔案是空的，會回傳錯誤訊息：「檔案內容為空，請重新上傳。」(422)
    - 這兩種情況前端都不該把網址存進資料庫，請提示使用者重傳

16. 下載的暫時性補救（已於 2026-09-15 上正式站）

- [Get] /download 找不到檔案時，會自動用檔名去雲端找同一份檔案回來
- 14 筆斷鏈中有 10 筆已經自動救回，使用者點下載都正常
- 真的找不到才會回傳錯誤訊息：「檔案不存在或已被移除，請聯繫課程老師重新上傳。」
- 這只是補救，不是根治
  - 壞掉的連結還是會繼續產生，只是使用者看不到錯誤
  - 前端改用 v3 之後才會真正停止產生

17. 編輯課程／表單時誤刪檔案的修復（已上正式站，前端無需改動）

- 問題: 編輯課程或其他申請表單時，會把「舊清單有、新清單沒有」的檔案實體刪除
  - 原本用「字串」比對，同一個檔案舊資料存純網址、前端送 JSON 格式，
    字串不同就被當成移除而刪掉，但 DB 其實還在引用 → 檔案遺失
  - 這是 20260908歷史書（一）.pdf 等檔案消失的原因
- 已改為「以實際物件路徑比對」，純網址與 JSON 混用都不會誤刪
- 前端維持原本送法即可，不需改動
- 注意: 此問題與上傳格式無關，前端接不接 v3 都已修復

18. 下載救援邏輯限縮（已上正式站，前端無需改動）

- 16 的救援原本「任何檔名」都會嘗試找同名檔案回傳
  - 副作用: 可用亂猜的檔名取得他人檔案
- 已改為兩道檢查:
  - 請求的連結必須確實存在於資料庫（亂猜的連結一律不救）
  - 補救用的同名檔案必須沒被任何資料引用
- 對正常使用者無影響，斷鏈仍會自動救回
