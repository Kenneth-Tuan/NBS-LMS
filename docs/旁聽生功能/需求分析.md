# 旁聽生需求整理

---

## 一、要解決什麼

老師在「學生名單」和「成績簿」要一眼看出：誰是旁聽、哪個科別。

旁聽生學費、名額與正科生相同；差在這門課不用交作業、沒成績、沒學分。

---

## 二、旁聽的定義

- **綁在「這門課的選課紀錄」**，不是學生帳號身分。
- 同一人可以 A 課正修、B 課旁聽。
- 不新增「旁聽生」角色。

---

## 三、誰看得到、誰能改

| 角色                           | 學生名單                       | 成績簿                                         | 註記旁聽                   |
| ------------------------------ | ------------------------------ | ---------------------------------------------- | -------------------------- |
| 老師                           | 看得到「旁聽」「科別」         | 看得到「旁聽」「科別」；不能改標記、不能打分數 | 不能改                     |
| 管理員／院長（Admin、Manager） | 看得到                         | 看得到                                         | **唯一可勾／取消旁聽的人** |
| 學生                           | 看得到科別；**看不到誰是旁聽** | 只看自己的成績；旁聽課沒分數                   | 選課時不能自選旁聽         |

「只有老師在成績簿上看得到」= 旁聽標記是教職員資訊，學生端不顯示。

---

## 四、畫面要顯示什麼

**學生名單、成績簿（老師／管理員）都要有：**

1. **旁聽** — 是／否（建議 Tag，不要只寫 true）
2. **科別** — 沿用現有科別（道學碩士、基督教研究碩士等）

---

## 五、業務規則

### 名額

旁聽**佔名額**。`已選人數 / 上限` 把旁聽算進去，滿額一樣不能再加。

### 學費

學費算法與正科生相同。

### 作業

這門課旁聽 = 不用交作業。學生看不到上傳；老師繳交狀況顯示「無需繳交」，不當未繳。

### 成績

這門課旁聽 = 無成績。成績簿該列不能輸入；已有分數被改成旁聽後，不再計成績、不能再改。

### 學分／成績單

這門課旁聽 = 無學分。成績單**仍列出該課**，註記「旁聽」，實得學分 0。

---

## 六、操作流程

1. 學生照常選課（或教務加選）→ 佔名額、算學費。
2. 管理員／院長在後台把該生在**該門課**標成旁聽。
3. 老師在學生名單、成績簿看到標記與科別。
4. 該生這門課：不交作業、老師不打分、成績單 0 學分。

老師不能在成績簿上改旁聽標記。

---

## 七、不在本次範圍

- 學生自行申請旁聽
- 旁聽改成獨立帳號角色
- 旁聽不佔名額、或學費另計
- 成績單隱藏旁聽課程（本次是列出＋註記）

---

對客戶可以一句話收斂：

> 旁聽是「某門課的修課方式」，由教務註記；佔名額、收同樣學費；老師在名單和成績簿看得到旁聽與科別；學生看不到這個標記；該課無作業、無成績、無學分，成績單列出並註記旁聽。

# 以下是後端可能需要修改的部分

## 後端

### 1. Data model

Enrollment（選課紀錄）加：

text
is_audit boolean default false
marked_by user_id nullable
marked_at timestamptz nullable

**不要**另開一種 enrollment type。旁聽生跟正科生走同一張表，這樣：

- enrollment_count 自動佔名額（現況不用改）

科別不新增欄位，join `users.departments`。

### 2. 既有 API 回傳擴充

**`GET /student-list?course_id=`**

現況前端只用 name / `email`。要加：

json
{
"student_id": "...",
"name": "...",
"email": "...",
"departments": ["master_of_divinity"],
"is_audit": true
}

權限：`is_audit` 只給 teacher / admin / manager / creator；學生打這支要 strip 掉，否則名單 tab 會漏。

**`GET /score/list-sheet?course_id=`**

data_rows[] 現況只有 student_id / student_name / `scores`。要加 `departments`、`is_audit`。

**`GET /assignment/student/list-by-course`**  
加 `is_audit`（或獨立 profile flag），學生端才能藏上傳。

**`GET /assignment/teacher/list-submissions`**  
每個學生帶 `is_audit`，老師看繳交狀況才知道誰「無需繳交」。

### 3. 新 API：註記旁聽

text
PATCH /enrollment/audit?course_id=&student_id=
body: { is_audit: true }
roles: admin, manager, creator

老師打 → 403。學生自己選課不能勾旁聽。

沒有現成「課程選課名單管理」後端，這支是新的。不要塞進 `PATCH /users/:id`——那會變成全域身分。

### 4. 業務規則（硬擋，不要只靠前端）

| 行為         | 改動                                                                |
| ------------ | ------------------------------------------------------------------- |
| 選課佔名額   | pick-course / 人工加選：旁聽照樣 `enrollment_count++`，滿額一樣拒絕 |
| 交作業       | `PUT /assignment/submit`：`is_audit` → 4xx                          |
| 打成績       | `POST /score/submit-score`：`is_audit` → 4xx                        |
| 學分         | 成績單計算跳過；`earnedCredit = 0`                                  |
| 學費         | **不排除**。註冊表仍算 credit \* fee                                |
| 學生看成績簿 | `POST /score/my-score`：旁聽生回空或明確 `is_audit`，不要回分數     |

建議旁聽列也出現在 score sheet（老師才看得到人），只是 scores 全 null。
